# How to Convert Text Case: Uppercase, Lowercase, Title Case & More

Accurate letter capitalization is essential for clear communication, professional publishing, and software engineering. Yet retyping paragraphs to fix caps-lock mistakes or converting database column names between naming conventions is tedious and time-consuming.

In this guide, we review the conventions and rules behind every major text case style and provide practical examples for both editorial and programming contexts.

---

## Editorial Case Styles

### 1. UPPERCASE (All Caps)
All letters in the text are capitalized:
> "IMPORTANT SYSTEM ANNOUNCEMENT"

**When to use**: Short headlines, acronyms, urgent alert banners, or legal disclaimers. Avoid using all-caps for long paragraphs, as it reduces reading speed and can feel like shouting.

### 2. lowercase (All Miniscule)
All letters are transformed to lowercase:
> "contact@example.com"

**When to use**: Email addresses, website URLs, and server commands where consistency avoids case-sensitive errors.

### 3. Title Case (Headline Capitalization)
The first letter of major words is capitalized, while minor grammatical words remain lowercase:
> "The Quick Brown Fox Jumps Over the Lazy Dog"

**The Golden Rules of Title Case:**
- **Always capitalize** the first and last words of the title, regardless of their part of speech.
- **Capitalize** nouns, pronouns, verbs, adjectives, and adverbs.
- **Keep lowercase** short prepositions (in, on, at, by, for, of, with), coordinating conjunctions (and, but, or, nor), and articles (a, an, the)—unless they begin or end the title.

### 4. Sentence case
Only the first letter of each sentence and proper nouns are capitalized:
> "The package arrived yesterday. Did you receive the confirmation receipt?"

**When to use**: Standard body prose, news article summaries, bullet points, and modern UI button labels.

## Programming and Developer Case Styles

In software development, spaces cannot be used in identifiers like variable names, file paths, and database keys. Different programming ecosystems have adopted standardized casing styles to replace whitespace:

### 1. camelCase
The first word starts with a lowercase letter, and every subsequent concatenated word starts with a capital letter:
> `userProfileData` or `calculateMonthlyInterest`

**Common ecosystems**: JavaScript, TypeScript, Java, Dart, and JSON keys.

### 2. PascalCase (UpperCamelCase)
Similar to camelCase, but the very first letter is also capitalized:
> `UserProfileController` or `PaymentGateway`

**Common ecosystems**: React components, C#, class names in Python, and TypeScript type declarations.

### 3. snake_case
Words are entirely lowercase and separated by underscores:
> `user_profile_data` or `total_purchase_count`

**Common ecosystems**: Python variables and functions, Ruby, Rust, and SQL database column names.

### 4. kebab-case (lisp-case)
Words are lowercase and separated by hyphens:
> `user-profile-data` or `main-header-container`

**Common ecosystems**: CSS class names, HTML attributes, and web URL slugs. You can also generate clean slugs using our [Slug Generator](/tools/slug-generator).

### 5. CONSTANT_CASE (SCREAMING_SNAKE_CASE)
Words are in uppercase and separated by underscores:
> `MAX_RETRY_ATTEMPTS` or `API_SECRET_KEY`

**Common ecosystems**: Global constants, environment variables (`.env` files), and configuration flags.
